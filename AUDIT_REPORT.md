# AUDIT_REPORT.md

Evidence-based audit of gptagent2, covering security, data-integrity
(look-ahead/leakage/survivorship), backtest realism, DB/performance, and
data-fabrication risk. Every finding below was verified by reading the
actual code and citing file:line evidence — nothing here is a generic
checklist item. Findings that were checked and found correctly implemented
are listed explicitly at the bottom so "checked and clean" is distinguishable
from "not yet checked."

This is the first installment of a much larger, explicitly multi-week audit
requested against this repo (22 phases: data quality engine, multi-factor
forecast engine, probability calibration, multi-horizon consistency,
walk-forward validation, full backtest metrics, 8-level agent hierarchy,
unified decision engine, regime-specific model weights, on-chain/derivatives
expansion, news/scanner upgrades, dashboard/Telegram redesign, 90% test
coverage, observability). This report and the fixes below cover Phase 0
(the audit itself) plus the CRITICAL/HIGH items found so far; it will grow
as later phases are worked through, in the same evidence-only style.

## Checked and verified correct (no finding)

- **`compute_forward_returns`** (`app/services/probability/engine.py:16-39`): windows `returns[i+1:i+1+horizon]` and returns `None` when the window runs past the series end or has a gap — no future data leaks into the empirical RSI-bucket forward-return statistic used by Probability/Forecast. This is descriptive ("historically, X% forward return followed this RSI reading"), not a claimed trade fill, so it is a fundamentally different (and correct) use of forward data than the backtest engine's now-fixed same-bar-fill bug above.
- **`app/services/history/indicators.py`**: RSI/MACD/ATR/SMA/volatility are all strictly causal — each output at index `i` uses only `closes[0..i]`.
- **`app/services/replay/engine.py`**: only reads other engines' already-persisted "latest" snapshots; performs no independent computation that could see future bars.
- **`app/services/analysis/regime.py`, `app/services/consensus/engine.py`**: no module/class-level mutable caches — no cross-symbol/cross-request data leakage.
- **CORS**: `app/main.py` has no `CORSMiddleware` configured at all (not a misconfiguration — nothing to misconfigure).
- **Telegram bot**: uses long polling (`dispatcher.start_polling`), not a webhook — no spoofable webhook endpoint exists.
- **SQL injection**: no f-string/`.format()`-built SQL found anywhere near `execute(` — all queries go through SQLAlchemy's parameterized `select()`/`insert()`.
- **Secret logging**: `app/main.py` redacts credentials from `DATABASE_URL`/`REDIS_URL` before logging; no `admin_api_key` or other API key is logged anywhere in the codebase.
- **On-chain / whale fabrication** (the project's top standing concern): `app/services/onchain/engine.py` and `app/services/whales/engine.py` are both honest — every metric not backed by a real, wired provider (DefiLlama, CoinGlass, CoinGecko) is explicitly `None` with a `reason` string. No `random.uniform`, hardcoded plausible-looking placeholder, or silent fake-data fallback found in either file.
- **News/sentiment**: `app/services/news/classifier.py` is an openly-documented keyword-lexicon classifier (no false ML claim). Dedup uses `ON CONFLICT (url) DO NOTHING` — no double-counting in sentiment aggregation.
- **Scanner opportunity ranking**: only reads `BreakoutEvent.probability_pct`, already persisted at detection time — no forward-looking leakage. The scanner universe explicitly preserves `ALWAYS_INCLUDE` symbols across refreshes; symbols dropping out of top-500 between 24h refreshes is a documented, bounded staleness window, not silent survivorship corruption.
- **Test coverage presence**: `app/services/onchain/`, `app/services/whales/` (`test_onchain_engine.py`, `test_whale_engine.py`, `test_coinglass.py`, `test_coingecko_derivatives.py`) and `app/services/scanner/` (6 test files) all have real test coverage. No `derivatives` package exists as a separate module — CoinGlass/CoinGecko derivatives data is covered inside the whales engine.

## What's real vs. scaffold (per the project's "never fabricate" rule)

- **Real, wired, live data**: crypto/stock/macro OHLCV history (CoinGecko/yfinance/FRED/Twelve Data/Alpha Vantage), news (RSS + keyword sentiment), on-chain TVL/stablecoin-supply/DEX-volume (DefiLlama, BTC/ETH/SOL only), derivatives funding/OI (CoinGlass, CoinGecko fallback), economic calendar (FRED).
- **Honest scaffold (explicitly reports "unavailable", never fabricates)**: exchange netflow/reserves, SOPR, MVRV, NUPL, dormancy, active/new addresses, large transfers (needs `GLASSNODE_API_KEY`/`HELIUS_API_KEY`, unset in this deployment).
- **Backtest**: now models a 1-bar execution lag and a documented fee/slippage assumption (this audit's fix) — still does not model funding cost, leverage, or liquidation risk (Phase 6 items not yet implemented).
