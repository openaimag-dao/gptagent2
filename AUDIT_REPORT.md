# AUDIT_REPORT.md

Evidence-based audit of gptagent2, covering security, data-integrity
(look-ahead/leakage/survivorship), backtest realism, DB/performance, and
data-fabrication risk. Every finding below was verified by reading the
actual code and citing file:line evidence — nothing here is a generic
checklist item. Findings that were checked and found correctly implemented
are listed explicitly at the bottom so "checked and clean" is distinguishable
from "not yet checked."

This is an ongoing installment of a much larger, explicitly multi-week audit
requested against this repo (22 phases: data quality engine, multi-factor
forecast engine, probability calibration, multi-horizon consistency,
walk-forward validation, full backtest metrics, 8-level agent hierarchy,
unified decision engine, regime-specific model weights, on-chain/derivatives
expansion, news/scanner upgrades, dashboard/Telegram redesign, 90% test
coverage, observability). This report and the fixes below cover Phase 0
(the audit itself, all CRITICAL/HIGH items found, plus several MEDIUM/LOW
ones) and the start of Phase 1 (Data Quality Engine, below); it will grow
as later phases are worked through, in the same evidence-only style.

## Checked and verified correct (no finding)

- **`compute_forward_returns`** (`app/services/probability/engine.py:16-39`): windows `returns[i+1:i+1+horizon]` and returns `None` when the window runs past the series end or has a gap — no future data leaks into the empirical RSI-bucket forward-return statistic used by Probability/Forecast. This is descriptive ("historically, X% forward return followed this RSI reading"), not a claimed trade fill, so it is a fundamentally different (and correct) use of forward data than the backtest engine's now-fixed same-bar-fill bug above.
- **`app/services/history/indicators.py`**: RSI/MACD/ATR/SMA/volatility are all strictly causal — each output at index `i` uses only `closes[0..i]`.
- **`app/services/replay/engine.py`**: only reads other engines' already-persisted "latest" snapshots; performs no independent computation that could see future bars.
- **`app/services/analysis/regime.py`, `app/services/consensus/engine.py`**: no module/class-level mutable caches — no cross-symbol/cross-request data leakage.
- **CORS**: `app/main.py` has no `CORSMiddleware` configured at all (not a misconfiguration — nothing to misconfigure).
- **Telegram bot**: uses long polling (`dispatcher.start_polling`), not a webhook — no spoofable webhook endpoint exists.
- **SQL injection**: no f-string/`.format()`-built SQL found anywhere near `execute(` — all queries go through SQLAlchemy's parameterized `select()`/`insert()`.
- **Secret logging**: `app/main.py` redacts credentials from `DATABASE_URL`/`REDIS_URL` before logging; no `admin_api_key` or other API key is logged anywhere in the codebase.
- **On-chain / whale fabrication** (the project's top standing concern): `app/services/onchain/engine.py` and `app/services/whales/engine.py` are both honest — every metric not backed by a real, wired provider (DefiLlama, CoinGlass, CoinGecko) is explicitly `None` with a `reason` string. No `random.uniform`, hardcoded plausible-looking placeholder, or silent fake-data fallback found in either file.
- **News/sentiment**: `app/services/news/classifier.py` is an openly-documented keyword-lexicon classifier (no false ML claim). Dedup uses `ON CONFLICT (url) DO NOTHING` — no double-counting in sentiment aggregation.
- **Scanner opportunity ranking**: only reads `BreakoutEvent.probability_pct`, already persisted at detection time — no forward-looking leakage. The scanner universe explicitly preserves `ALWAYS_INCLUDE` symbols across refreshes; symbols dropping out of top-500 between 24h refreshes is a documented, bounded staleness window, not silent survivorship corruption.
- **Test coverage presence**: `app/services/onchain/`, `app/services/whales/` (`test_onchain_engine.py`, `test_whale_engine.py`, `test_coinglass.py`, `test_coingecko_derivatives.py`) and `app/services/scanner/` (6 test files) all have real test coverage. No `derivatives` package exists as a separate module — CoinGlass/CoinGecko derivatives data is covered inside the whales engine.

## What's real vs. scaffold (per the project's "never fabricate" rule)

- **Real, wired, live data**: crypto/stock/macro OHLCV history (CoinGecko/yfinance/FRED/Twelve Data/Alpha Vantage), news (RSS + keyword sentiment), on-chain TVL/stablecoin-supply/DEX-volume (DefiLlama, BTC/ETH/SOL only), derivatives funding/OI (CoinGlass, CoinGecko fallback), economic calendar (FRED).
- **Honest scaffold (explicitly reports "unavailable", never fabricates)**: exchange netflow/reserves, SOPR, MVRV, NUPL, dormancy, active/new addresses, large transfers (needs `GLASSNODE_API_KEY`/`HELIUS_API_KEY`, unset in this deployment).
- **Backtest**: now models a 1-bar execution lag and a documented fee/slippage assumption (this audit's fix) — still does not model funding cost, leverage, or liquidation risk (Phase 6 items not yet implemented).

## Phase 1: Data Quality Engine

Started this phase by verifying the previous PR's fix live, which surfaced a real, previously-undocumented gap:

**Live discovery.** Triggering a backtest for AAPL returned 404 ("no history synced"). Checking further: `GET /api/history/<symbol>` returns 404 for **every** `STOCK_TICKERS`, `INDEX_TICKERS`, and `MACRO_YFINANCE_TICKERS` symbol (AAPL/MSFT/NVDA/TSLA/AMZN/META/GOOGL, NASDAQ/SPX/DJI/RUT, DXY/GOLD/SILVER) on this live deployment — zero rows, for all of them — while CoinGecko-sourced crypto (BTC) has data. Triggering `/api/admin/sync-history` and reading Railway's logs confirmed the root cause is external, not a code bug: yfinance is returning empty/malformed HTTP responses from this environment (`JSONDecodeError('Expecting value: line 1 column 1 (char 0)')`), most likely Yahoo Finance blocking or rate-limiting the datacenter IP range — a known operational reality of yfinance, not something fixable from this side. The sync pipeline's own retry logic (`app/services/market/yfinance_utils.py`) already retries up to 4 times and gives up cleanly.

**The actual gap worth fixing.** `app.services.history.pipeline.run_validation()` — the existing gap/duplicate checker that runs after every sync — explicitly does `if not rows: continue` for every symbol/timeframe with zero stored rows. So a total, silent provider failure across an entire asset class was invisible everywhere except raw process logs reachable only via `railway logs`; `/api/admin/sync-history`'s own status just reports `"state": "done"` regardless of whether any given provider actually wrote anything.

**Fix — `app/services/data_quality/engine.py` (`DataQualityEngine`).** A registry-wide sweep (`assess_all()`) that reports, per symbol/timeframe, `status` ("empty" or "has_data"), `row_count`, `most_recent_timestamp`, and `days_since_last_update`. Deliberately does **not** invent a staleness threshold — different tables have very different natural update cadences (daily OHLCV vs. monthly FRED macro releases), and guessing wrong would either cry wolf on legitimately-slow series or hide a real gap on fast ones; only "zero rows at all" is treated as a hard, unambiguous status. Exposed via `GET /api/data-quality` (public read, no auth needed — informational only, no cost) and a new Telegram `/dataquality` command. Does not duplicate `run_validation`'s gap/duplicate-repair logic — it complements it by reporting exactly the symbols `run_validation` currently skips.

**Follow-up — actually closing the yfinance gap (`TwelveDataHistoricalProvider` + `FallbackHistoricalProvider`).** `TWELVEDATA_API_KEY` and `alphavantage_api_key` turned out to already be configured on this deployment (an earlier check in this session used the wrong env var names and wrongly concluded neither was set). Live-verified both against the real APIs before writing any code:
- **Alpha Vantage**: free tier is 25 requests/day and was already exhausted by other usage (`SentimentEngine`'s news fallback) at time of testing — not viable as a reliable historical backfill source. Not used.
- **Twelve Data**: `/time_series?outputsize=5000` returns up to ~20 years of daily bars in one call. Live-verified working for individual equities (`AAPL` → 5000 candles back to 2006) and spot forex/commodity pairs (`EUR/USD`, `XAU/USD`, `XAG/USD` — no volume field, as expected for spot FX). Live-verified **NOT** available on the free tier for indices or DXY (`"This symbol is available starting with the Grow or Venture plan"` for `NASDAQ`/`SPX`/`DJI`/`RUT`/`DXY`) — tried multiple symbol-format variations before concluding this is a real plan restriction, not a lookup mistake. Free tier is rate-limited to 8 credits/minute (hit this live while testing).

Added `app/services/history/providers/twelvedata_provider.py` (`TwelveDataHistoricalProvider`, daily-only, self-paced to stay under 8 calls/minute via a module-level rate limiter) and `app/services/history/providers/fallback_provider.py` (`FallbackHistoricalProvider`, a generic primary/fallback composition: tries yfinance first, only calls Twelve Data when yfinance returns zero candles — auto-recovers to yfinance-only with no code change if Yahoo's block ever lifts). Wired into `registry.py` for `STOCK_TICKERS`, `FOREX_TICKERS`, and `MACRO_YFINANCE_TICKERS` (GOLD/SILVER; DXY stays unresolved since no working symbol was found). `INDEX_TICKERS` (NASDAQ/SPX/DJI/RUT) deliberately left yfinance-only — no viable free-tier path exists for those today. End-to-end verified against the real API (not just mocks): `AAPL` and `EURUSD` fetches both return correctly-parsed, chronologically-sorted candles.

**Net effect**: closes the gap for 15 of the 20 originally-empty symbols (7 stocks + 6 forex pairs + gold/silver). The 4 indices and DXY remain a known, documented gap with no free-tier fix available — visible going forward via `/api/data-quality` and `/dataquality` rather than silently missing.

## Remaining risks

1. The dashboard's admin-key prompt is a shared secret cached in browser `localStorage`, not a real per-user credential — appropriate for this project's current single-operator architecture (no user accounts anywhere in the schema), but worth revisiting if this ever becomes multi-user.
2. Backtest results are still single-symbol, fixed-universe (survivorship-exposed for equities), and do not yet include Monte Carlo resampling *of the fee/slippage-adjusted* return series (the existing `monte_carlo_simulation()` in `strategy.py` resamples real historical trade returns and does not yet see the new cost-adjusted returns from this fix — worth reconciling in a follow-up).
3. **NASDAQ/SPX/DJI/RUT/DXY still have no historical backfill path** — yfinance is blocked and Twelve Data's free tier doesn't serve indices or DXY via `/time_series`. Would need a paid Twelve Data plan, a different provider, or accepting this as a permanent gap for these 5 symbols specifically. Visible via `/api/data-quality`.
4. The next admin-triggered `/api/admin/sync-history` run needs to actually execute against the live deployment to backfill the now-fixed 15 symbols — this PR ships the mechanism but the backfill itself only happens once triggered (or on the next scheduled sync, if one exists).
3. Phases 1–22 of the requested scope (Data Quality Engine, multi-factor Forecast/Probability Calibration, multi-horizon consistency, walk-forward validation, 8-level agent hierarchy, unified Decision Engine, regime-specific weights, derivatives/on-chain expansion, news/scanner upgrades, dashboard/Telegram redesign, 90% coverage, observability) have not been started — this report will be extended as each is worked through.
